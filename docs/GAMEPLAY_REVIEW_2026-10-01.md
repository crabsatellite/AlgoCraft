# AlgoCraft 生存玩法与内容闭环审核（2026-10-01）

本文保留玩法审核封存时的结果与历史 JAR。后续已完成模型、界面和服务器题库改版，当前交接版本请使用[服务器题库交付记录](SERVER_BANKS_2026-10-01.md)中的产物与收据。

本轮检查的是玩家从生存开局到获得、使用和收藏奖励的完整路径。题库、UI 和判题通过测试，并不能单独证明这条路径成立。

## 判断

原有版本没有闭合：电脑只有创造物品栏入口，没有合成配方或挖掘掉落；全通成就没有接到发奖流程。普通解题奖励已经存在，但里程碑、周奖励和跨维度进度存在重复领取问题。

本轮补齐后，当前实现具有可供手测的基础循环：**采集材料 → 合成并放置电脑 → 写 Java、运行、提交 → 获得生存资源和成就 → 使用资源、展示奖杯 → 追求更难题目或全通**。它的定位仍是带生存奖励的算法练习模组。长期经济平衡和玩家是否愿意持续游玩，不能由自动化测试代替。

## 修复

- 补齐电脑配方、配方书发现、掉落表和采掘工具标签。
- 里程碑资源只在新的独立题目使计数达到 10／25／50／100／200／500 时发放。重做旧题不再重复领取。
- 连续打卡的额外经验和每 7 天的周物品只在当天第一次符合奖励条件的提交时发放。
- 将全通成就接到服务器判定通过后的实际奖励流程，默认库最后一题可以获得下界合金全通奖杯。
- 进度和成就归属同一世界内的玩家 UUID，各维度共用；成就管理器随存档实例保存，避免不同世界共用进程缓存。
- 旧维度记录一次性合并到主世界，题目 ID 去重、时间戳取最新值、成就取并集；不删除或重写旧维度数据文件。旧数据没有逐题难度，已删除的自定义题无法精确重建难度分布，迁移保留其原计数的最大值。
- 禁用奖励时仍保存解题进度和统计，不发物品、经验或奖杯。
- 随机附魔书实际写入可用附魔；终局奖励等级实际读取屠龙或信标进度。
- 发奖前记录物品副本，避免背包插入消耗 ItemStack 后奖励摘要显示零个。聊天显示本次物品、经验和满背包掉落规则，保留中英文格式。

## 奖励与边界

首次解题根据难度和阶段给原版资源及经验；同一道题隔一个服务器自然日可以领较小的复习奖励，同日重复提交不发奖。不同新题的首解奖励可以在同一天领取。奖励直接进入背包，装不下则掉在玩家脚边，遵循原版物品拾取和消失规则。

500 道独立题目的资源里程碑给龙蛋；默认官方库全通给下界合金奖杯。这两件事分别按独立题数和具体题库的 ID 集合计算。完成后可以复习或加载自定义题库，没有额外结局章节。

本轮没有重做奖励数值。晚期每道困难题的首解配表包含下界之星，这会明显加快部分原版生存目标；每天重做已知答案也能获得资源。因此“奖励正常可获得”成立，不代表“生存经济已经平衡”。

## 有趣的部分与不足

对愿意写 Java 和学习算法的玩家，解题反馈、拿资源建设基地、收集带自己名字的奖杯有明确吸引力。解题成果能留下可展示的物品，比仅显示通过数量更有记忆点。

目前世界和算法仍然联系较弱：玩家主要坐在电脑前完成题目，成长主要增加资源和收藏；没有电脑升级选择、代码驱动的方块行为、合作任务或章节带来的世界变化。我的评价是“已有有趣的核心，适合算法学习者手测”，尚不能证明普通生存玩家会长期投入。

下一轮内容设计应优先增加一个能改变基地玩法的专题目标，例如完成路径专题后获得路线规划能力，并为奖励设置有选择的用途；先验证一条新循环，再增加题量。
