# 服务器题库与多人提交

AlgoCraft 的公共题库由服务器统一发布。玩家加入时自动获取服务器清单、题面、示例、初始代码、翻译和配图；同步包不携带隐藏测试与参考解答。游戏内 IDE 和 Web IDE 的公共题提交都通过当前 Minecraft 玩家连接，由服务器判题、记录进度和发放奖励。

## 管理员操作

需要 Minecraft 权限等级 2；服务器控制台也可执行。聊天框使用 `/` 前缀，控制台不加 `/`。

| 命令 | 用途 |
| --- | --- |
| `/algocraft bank list` | 查看服务器已加载的题库、题数及启用状态 |
| `/algocraft bank install <name> <url>` | 下载、校验并发布远程题库；中文或含空格的名称用双引号，URL 使用原有题库 manifest 格式 |
| `/algocraft bank enable <id>` | 启用已加载的题库；ID 使用 list 显示的规范化名称 |
| `/algocraft bank disable <id>` | 停用题库并同步在线玩家 |
| `/algocraft bank reload` | 重新加载服务器目录中的题库，校验成功后整体发布 |
| `/algocraft bank update-official` | 更新服务器官方题库，成功后整体发布 |

新世界默认只启用 `official`。服务器题库文件继续使用 `algorithm_challenges/repos/`，启用状态和服务器缓存身份保存到世界的 `algocraft_data`。管理员也可明确启用服务器 `algorithm_challenges/user/` 中的 `user` 题库。导入界面的普通玩家操作始终属于个人练习；单人世界房主导入后，也需要管理员明确启用才能成为公共题库。

中文题库 ID 也使用双引号，例如 `/algocraft bank enable "课堂"`。

校验或更新失败时，保留正在使用的发布快照。一次只接受一项管理员更新操作；发布完成后自动通知所有在线玩家，新加入的玩家取得同一版本。

## 玩家操作和数据边界

- 题库选择器区分“服务器”和“个人练习”。本地导入不上传、不公开，也不产生服务器奖励。个人题目使用 `practice:` 身份，与公共题目分离。
- 正式提交携带题库 ID、题目 ID、内容版本及请求 ID。服务器同时校验题库身份和版本；停用、过期或伪造的引用直接拒绝。判题期间版本变化或玩家断线，也不会按旧版本发奖。
- 客户端不再先用本地隐藏测试宣告公共题通过。提交按钮保持等待状态，直到收到对应的服务器结果；编译诊断可以回传，私有测试输入、预期值和运行输出不回传。
- 缓存按世界身份与发布哈希分隔，保存到 `config/algocraft/server-cache/<world-id>/`。完整校验后一次性启用；损坏缓存重新下载，旧版本分块不能覆盖新清单。
- 服务器学习进度按世界与玩家 UUID 保存。客户端仅保留当前连接的服务器进度，断线或换服清空该状态，个人练习记录继续保留在本地。
- 更新同一题目的内容不会重置首次通关或既有每日奖励限制。进度使用稳定题目 ID，内容版本用于保证判题一致性。新增题目应使用新 ID；换题库名称意味着创建不同的题库身份。
- 新的游戏内草稿按世界身份分隔。旧通用草稿文件保留，避免把来源不明的旧草稿自动带入其他服务器。

随 JAR 内置的官方题库本身包含测试与参考解答，方便离线练习，因此官方题不能视为保密考试题。服务器额外安装的题库只同步公开部分；无论玩家本地掌握什么内容，公共通关、进度和奖励都由服务器实际判题决定。

## Web IDE

浏览器访问玩家自己电脑上的 loopback 服务，公共题目来自当前游戏连接的服务器目录。Web 提交转发给对应 Minecraft 玩家，由同一条服务器判题路径处理；题库改变时页面自动更新目录，旧页面版本提交返回冲突提示。

专用服务器不再启动未经玩家绑定的本机 Web 判题服务。它不需要向公网开放 HTTP 端口。客户端和服务器需要同时更新到本次 JAR；网络协议从 1 升到 2，旧客户端不能混用。
