## Review Standard

Each problem is reviewed across five dimensions:

- Statement: the prompt, examples, constraints, and edge cases must be clear.
- Tests: reference tests must cover normal cases, boundary cases, duplicates,
  empty/small cases where allowed, and the key trap cases for the topic.
- Solutions: official solutions must teach distinct ideas, data models,
  invariants, or tradeoffs. Cosmetic rewrites do not count.
- Chinese: `zh_cn` must cover the same solution set and be usable as lesson text.
- Visuals: diagrams must make the rules or a labeled example understandable and
  remain readable in game. Valid example outcomes are allowed when their context
  is explicit; avoid algorithm recipes and illustrations that contradict input.

Status key:

- `PASS`: reviewed and currently acceptable as textbook material.
- `FIXED`: reviewed and improved in this pass.
- `INTENTIONAL`: reviewed; a seeming weakness is intentionally kept because a
  common alternative would teach the wrong constraint or add no real value.
- `NEXT`: not reviewed yet in this sequential pass.
